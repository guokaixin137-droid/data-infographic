# 大批量文本

先决定什么东西算“一份”。反馈工单可以按工单计数，阅读笔记可以按原始文章计数，访谈可以按受访者计数。记录文档、作者或受访者、日期、语言、来源标识和可用定位。用适合本项目的字段即可。

1. **盘点和分批**。先列出材料，保留来源层级。长报告按章节，文章合集按篇，反馈按记录或会话。量大时分批，并让批次覆盖来源、时段及类别。抽样时记录样本怎么选，以及读到多少份。保留未取得、为空与重复的记录数。
2. **逐批取证**。每个有用片段留下“原始记录 ID、位置、主题、数值和单位或可复核的原话”。PDF 保留文件和原页码，文章保留标题/小节或段落，访谈保留说话者和时间点。对相互矛盾的说法保留各自的适用范围。
3. **跨批合并**。统一同义标签和单位。文档可能跨多个片段，一份文档也可以谈多个主题。计算“多少份提到”时按原始文档去重。引用次数、文档数和受访人数分别统计。多标签比例允许合计超过 100%，在图例里写明分母。
4. **从定位回读**。对核心结论、跨批异常和准备用的引语回读原文，并从同一份核对后的明细派生首屏和图表。把按材料整理的内容证据留给选题；用色另查公开资料。

## 做一张信息密集的全景图

从同一张记录明细表起步，分别问“什么最常见”“哪些事情同时出现”“在哪一组或哪个阶段特别突出”“个案如何解释这个差异”。先整理出能回答的发现，再决定版面。比如读者来信可以把诉求排名和读者群体交叉起来，到原信里找一封能解释反常格子的例子。检查多个模块是否只是在重画同一个总数。

用几个样本先定主题边界。一次检索只用来找候选段落，结合上下文判断是否明确谈到该主题。比如把一位嘉宾提出的做法计入“讨论过”，写结论时就说“若干期讨论过”，实际采纳率需要另外的证据。

建一份逐条明细。每个已审阅的原始记录有稳定 ID，下面挂零个或多个片段，每个片段留主题、页码或时间码及一句释义。未命中的已审阅记录保留在分母里。另记未取得、排除或只抽到一部分的材料，并在图旁交代本次覆盖和筛选依据。

主题频次等于各主题下不同记录 ID 的数量。共现取两个主题 ID 集合的交集，同一记录里分属两段也算。矩阵对角线应等于相应主题总数，对称格应相等，点开任意格所列的不同记录数应等于格内数字。不同主题的总数可以大于已审阅数。模板的 `themes` 图块直接从逐条明细算出两图和回查名单，字段见[模板与导出](rendering.md)。静态海报保留数值、口径和代表性出处。

## 本地纯文本

对 UTF-8 的 TXT、MD 或 Markdown 文件，可以在技能目录运行下面的命令。输入可以是单个文件或包含子目录的文件夹。将输出放在项目的工作目录，按需分批读取 JSONL。

~~~sh
python3 scripts/chunk_text.py ./materials ./chunks.jsonl --max-chars 12000
~~~

工具按相对路径和原文顺序写入，尽量沿行边界分段。极长的单行按字符切分。每条包含 source、part、起止行、起止字符和 text，字符区间从 0 开始且右端不含，行号从 1 开始。坐标以去掉 UTF-8 BOM、换行统一为 LF 的文本为准。空文件保留为 part 0。用 source 配合原始业务 ID 做统计，块号只用于定位。对 PDF、网页、转录接口或结构化反馈，可使用相应的读取工具并保留其原生定位。
